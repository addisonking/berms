# contribution schema v1

The ZIP contains contribution.json and passes/UUID.json arrays. NSFileCoordinator's single enclosing directory is also accepted. There are no arbitrary payload files. JSON uses UTF-8. Timestamps carry a UTC offset; Swift exports fractional ISO 8601. Raw samples additionally carry timestampSeconds (epoch seconds) to preserve original Date precision; all local snapshots use numeric epoch seconds.

Contribution fields: schemaVersion=1, immutable UUID id, createdAt, catalogID, baseRevision, baseChecksum (exact surveyed GeoJSON SHA256), provenance=`developerGPS`, contentVersion, optional note, operations, passes. Re-export retains id; edits explicitly increase contentVersion. All passes must belong to an operation in this archive.

Operation fields: kind (`addTrail`, `corroborateTrail`, `editTrail`), immutable slug, trailID, baselineHash, baseline (full original Feature or null), proposed (explicit full Feature or null), passIDs, selectedPassID. A corroboration proposal must be null. Existing operations require baseline values/hash; overlapping edits require an unchanged current baseline hash. New slugs are `survey-` plus a UUID assigned once, and never change with display names. Trail UUID bytes are SHA256(`namespace:slug`)[0:16], byte 6 adjusted to version 5 and byte 8 to RFC variant; exactly the existing Swift stableID implementation. Aliases resolve before identity comparison.

Pass fields: immutable UUID id, startedAt, endedAt, direction (`forward`, `reverse`, `unknown`), gaps (start/end intervals), exclusions (unique zero-based indices), optional interruption, samplesFile, checksum (SHA256 exact payload bytes). Pause/resume and long gaps create separate passes in phone exports, with interruption reason rather than joined coordinates. No sample predates its pass, exceeds its end, or moves backward in time. Each sample contains timestamp, latitude, longitude, horizontalAccuracy, verticalAccuracy, altitude, speed, course; unavailable quality values are explicit JSON null. Negative availability sentinels never become invented zeros. Source catalogs are approved/imported geometry, not GPS observations. Archived evidence retains that distinction.

Feature baseline hashing and contribution-ledger fingerprints are computed **only by the Python tools**: recursively normalize integral floats to integers; sort object keys; emit compact UTF-8 JSON with non-ASCII text unescaped and non-finite numbers rejected; append one LF. SHA256 covers those bytes. Swift never reproduces this canonicalization; it preserves baseline feature values and exports the Python-generated manifest hash. Package hashes cover raw file bytes instead. Changing unknown properties/attribution changes the feature baseline too.

The manifest uses the existing resorts.json schema plus revision and catalog checksum/url/trailHashes. Catalog version is its file checksum, so importing the same package is idempotent independent of app versions. Immutable URLs are set while packaging. Manifest revision is SHA256 of canonical manifest content before the revision field is added. App build identity remains independent.
